# 0.8.6 安全边界与逐规则审计

- 本版自动修改白名单为空（跨平台）。planner 无步骤，执行器独立无条件拒绝外部/旧计划；CLI fix/apply/repair 在读取会话或创建目录之前拒绝。没有 shell、原生修改、备份命令、确认默认放行或未识别动作回退。即使明确 yes 也不执行；未来启用白名单须另行安全评审，不能借空确认或非TTY放行。
- docs/SAFETY_RULE_AUDIT.csv 枚举225个静态引用规则ID（含历史/兼容ID，**不是225个实测检测点**）。每条共享planner/executor/display/advice不变式纳入单测；检测正确性和每种环境并未因此全部实测。
- UID0别名与root共享内核安全身份，用户按名字选择进程最终仍按数字UID匹配；进程1冲突是UID共享后果，不意味着应终止它。真实init通常拒绝SIGKILL，但其他root业务/SSH进程会受害。账户名、创建者、NSS和共享home需核实；锁口令或改shell不根治既有进程/定时重建。
- 安全账号处置顺序：保留有效root/admin与备用控制台；由授权管理员在安全位置备份账户数据库并严禁泄漏shadow；区分local/NSS，核实共享home和业务依赖；关联cron/timer/service/脚本及创建日志；仅确认恶意后审核按名字的本地精确变更。数据库锁、原子替换、passwd/group/shadow/gshadow一致性、NSS和业务验证未经实测时，本工具明确阻断，不给强制删除或手写编辑命令。
- timer高频或自定义路径仅线索，不能仅凭注释“日志清理”就放行；标准run-parts不是后门。核实timer→service→有效ExecStart、drop-in、enable链接、软件包来源与日志。当前扫描器不保证完整运行态关联，必须明确该缺口；FACT不得生成停服/删除命令。
- 本次考场原机已不可访问，属于事故复盘；不声称恢复了原业务，也不伪造真实控制端/flag。

正式AI平台业务/合法API Key、正式知识库恢复、Agent工具登记与批准基线逐项比对、自动执行/确认要求、系统提示词、长期记忆、debug敏感信息、归档口令轮换，以及按两个月正常业务日志溯源，均需要平台本身数据。只列安全顺序：保留业务与证据→核对批准基线和调用链→恢复批准工具/正式知识库→清理已确认的记忆/提示注入与debug泄露→仅轮换允许的应用凭据并验证业务→精确处理已确认主机持久化→复扫及不复活验证。**题目禁止改root密码/SSH公钥，此限制不等于禁止轮换其他已泄漏应用凭据。**
